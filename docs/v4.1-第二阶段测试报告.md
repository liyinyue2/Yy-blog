## 2. 问题清单

| 编号 | 所属模块 | 问题描述 | 严重程度 | 修复状态 |
|---|---|---|---|---|
| P2-1 | 首页 | `/api/settings` 每次加载被请求两次（社交组件绕过设置单例） | 中（重复请求） | 已修复 |
| P2-2 | 文章 | 阅读数从不自增：详情页"N 次阅读"与概览"总阅读"是死数字 | 中（功能缺失） | 已修复 |
| P2-3 | 审计 | 动作名中英混用（`article-更新` / `article-创建`），面板直接展示 | 低（数据一致性） | 已修复 |

### 复核后判定为“非缺陷”的项

| 现象 | 结论 |
|---|---|
| `/api/stats` 未登录返回 401 | 正确：仅后台使用，公开首页不调用 |
| 待办空内容、笔记超长返回 422 | 正确：Pydantic 模型约束（`min_length` / `max_length`），前端有对应提示 |
| 订阅填 `bad-email` 无应用层提示 | 浏览器原生 `type=email` 校验先拦截；填 `bad@x` 时应用层提示"请输入有效的邮箱地址。"，实测通过 |
| 文章不存在显示"文章不存在或已被移除"而非 404 页 | 正确：详情页自带空态与返回入口，比整页 404 更合适 |

## 3. 修复记录

| 文件 | 问题 | 修复方式 |
|---|---|---|
| `frontend/src/components/SocialLinks.vue` | 重复请求设置接口 | 改用 `loadSettings()` 单例，与 App.vue 共用同一次请求（首页 API 调用 2 → 1，重复 1 → 0） |
| `app/modules/blog/service.py` | 阅读数无自增 | 新增 `views_of()` / `bump_views()`；不放在 GET 里，避免读接口产生副作用 |
| `app/modules/blog/router.py` | 同上 | 新增 `POST /api/articles/{slug}/view`，同一 IP+文章 20 秒内只记一次（`rate_hit`） |
| `frontend/src/pages/PostView.vue` | 同上 | 详情加载后上报一次，用返回值刷新显示；失败静默不影响阅读 |
| `app/modules/blog/service.py` | 审计动作中英混用 | `article-更新/创建` → `article-update/create`，与其余动作统一 |

数据库：无结构变更、无迁移、无数据删除。
API：仅新增一个上报端点，其余接口签名不变（向后兼容）。
